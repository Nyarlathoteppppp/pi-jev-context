# v0.5 follow-up hardening

## Scope

Keep deterministic matching unchanged. Independently configure active fresh-output
Jev sieve; preserve prior message bytes, stable tools and original-output recall.
No context handler or third-party compaction was added.

## Corrections

- The initial lifecycle test incorrectly restored an in-memory session through an
  undefined file path. It now reconstructs a new installed-SDK SessionManager from
  actual entries and the leaf, and checks branch originals and exact recall text.
- Explicit dedupe on overrides compatibility shadow behavior, not only its config.
- Stack frames are independently protected; a double-escaped Caused-by regex was
  corrected. Actual JS/Python/Java/Go lines are tested across small block boundaries.
- Negative/out-of-range Jev probabilities are rejected rather than clamped to zero.
  Choice confidence and selected probability are also validated.
- Empty numeric environment strings no longer become zero. Invalid numeric values
  use defaults; threshold remains strict `< 0.10` by default.
- A single recognized command is required, with an optional simple `cd ... &&`
  prefix. `echo npm test` and mixed test-plus-other-command output are ineligible:
  the old substring search could wrongly classify source or unrelated evidence.

## Test boundaries

The lifecycle harness uses the installed Pi 0.86.1 SessionManager with simulated
extension event dispatch. It covers concurrent aliases, active branches, new
extension rebuild, sibling isolation, appendCompaction boundaries, unchanged
compacted-away read behavior, fresh post-compaction sieve, stable tools, and
failure retention. It does not simulate real disk exhaustion or execute the
native LLM compaction pipeline. HTTP tests run a local fixture server for timeout,
malformed, 429 and 503; these establish fail-open behavior, not provider uptime.

## Live methodology

The filesystem benchmark fixes fixtures and predicates before calls. A=off,
B=dedupe only, C=dedupe+active sieve. Results use unique output paths.
The first run deliberately remains on record even when sieve rewrites are zero.
A focused follow-up changes the instruction wording, without weakening guards or
changing filesystem acceptance, to avoid common-word overlap with every PASS line.
Do not combine these as identically distributed repetitions.

Failure-exit output should remain full. Multiple-failure diagnostic fixtures exit
zero to test active sieve. Delayed facts test warning retention and retrieval of a
previous run label. Model-generated assistant intent varies between runs, so guard
coverage and Jev decisions can vary. Empty cache counters cannot prove cache
preservation; prior-message byte preservation is separately checked by tests.

Recall is an escape hatch, not capability equivalence. Small synthetic pilots and
real-session dedupe savings do not prove safe future-value selection on real logs.

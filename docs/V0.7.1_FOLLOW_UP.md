# v0.7.1: common shell wrappers and actionable recall feedback

**Model performance first. Token savings second.**

This is the small follow-up discussed as “v0.71”; the package uses SemVer 0.7.1.
There are two changes. Jev questions, thresholds, hard KEEP rules, dedupe freshness,
original storage, and tool declarations stay unchanged.

## Common command forms

A small literal shell lexer recognizes these wrappers around already supported
executables:

```sh
cd "my repo" && npm test
CI=1 npm test
env CI=1 pnpm test
npm test 2>&1
cd "my repo" && CI=1 npm test 2>&1
npx --no-install vitest run
npx -y vitest run
npm run test:unit
npm run build:production
```

Quoted/escaped operands stay operands; an `&&` inside a quoted test name is not a
command separator. Classification uses executable/subcommand positions rather
than searching all arguments for a known command. A trailing stderr merge only
combines the output streams of the same command. Nothing is executed, expanded,
or rewritten by this parser.

Supported environment values are literal. Pipelines, command substitutions, other
redirections and multiple actual commands still pass through. This is a small
recognized grammar, not a complete Bash parser or a guarantee about arbitrary
package scripts. Declaring a command eligible does not guarantee any block will
be hidden. Jev failures still preserve the received output.

## Recall feedback

The same recall tool now distinguishes an empty branch store, an unknown source
id, no lexical matches, partial matches, exhausted pagination, and an insufficient
chunk budget. It reports the searched source count and unmatched query terms or
literal identifiers. When relevant, it provides up to five recent source ids,
line counts and command summaries, with exact line retrieval instructions.

Ranking and raw chunk text are unchanged. A no-match result is never a claim that
a fact does not exist. A match on `region` is explicitly insufficient to establish
a match on `DatabaseMigration`. The model may still inspect the full original;
there is no forced stop, automatic full-text injection, or repeated-search gate.
Navigation metadata adds some tokens and is outside the chunk budget as before.

## Measurements

### Recall response comparison

```sh
node bench/live/v071-recall.ts --reps 2 --out results/live-v071-recall-01.json
```

Model: `antigravity/gemini-3.8-flash`. Eight tasks per condition: needed fact,
absent component, alternate wording, and too-small initial budget, each repeated
twice. The last two cases explicitly prescribe the first query; they test recovery,
not spontaneous query formulation. Only write/recall tools are available. Both
conditions use the same declaration, hints, originals and filesystem grading.
The baseline search implementation is frozen from v0.7.0 commit 96371e2.

| Condition | Pass | Recall calls | Estimated returned tokens | Reported input tokens | Total latency |
|---|---:|---:|---:|---:|---:|
| v0.7.0 | 8/8 | 22 | 18,304 | 82,991 | 67.0s |
| v0.7.1 | 8/8 | 14 | 16,378 | 65,751 | 55.6s |

Absent-component cases improved from nine to four total recall calls and 23.5s
to 15.5s. Alternate-wording cases used fewer calls but returned more text (2,120
versus 7,255 estimated tokens), because one run inspected the full original.
Too-small-budget cases also took slightly longer overall. The sample supports
better navigation, not universal token/latency improvement or capability equivalence.
There were no provider/tool errors. All cache counters were zero. No Jev is called
by this retrieval benchmark.

### Actual wrapped bash commands

```sh
node bench/live/v071-commands.ts --out results/live-v071-commands-01.json
```

The model executes `cd "fixture app" && CI=1 npm test 2>&1`, fixes only the state
file, and reruns the same command. Filesystem grading checks the repair and
preservation of the test script and package manifest. Both conditions passed,
each running the exact command twice and no other bash command. v0.7.0 made no Jev
calls; v0.7.1 made two decisions, one rewrite, zero Jev failures and zero recalls,
saving 8,682 estimated net tokens. Both runs took about 15.5 seconds. This is one
synthetic wrapper fixture, not proof of broad log-filtering safety.

### Local workload replay

```sh
node bench/command-replay.ts > results/command-replay-v071.json
```

Across 26 non-temporary session files, 2,792 bash results and 148 long outputs,
both classifiers recognize 45 commands. There are no newly classified historical
results and no previously recognized commands lost. No output passes the complete
sieve eligibility rules. The new syntax support therefore has **no demonstrated
coverage gain in this historical sample**. Only aggregates are recorded; no
private commands or output text are published.

The separate read replay covers 27 files and 3,847 reads, with 20 rewrites saving
about 13K estimated tokens. Its inclusion rules differ from the command inventory.

## Official Jev guidance considered

TypeSafe's [known limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13)
recommend literal, narrow questions and code for exact computations; unrelated
state and indirect reasoning can reduce accuracy. Its
[semantic-search example](https://docs.typesafe.ai/cookbooks/semantic_find)
distinguishes ranking from evidence that an answer exists. These support keeping
parsing and match diagnostics deterministic. They do not justify adding a model
that declares historical facts absent, or loosening thresholds. No Jev prompt or
probability policy was changed in this patch.

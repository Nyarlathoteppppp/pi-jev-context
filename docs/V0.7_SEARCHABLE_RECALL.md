# v0.7: searchable historical originals

**Model performance first. Token savings second.**

## Behavior

`context_recall` accepts optional `query`, `id`, `budget`, and `offset`; existing
id/offset/limit calls keep their meaning. Search is a deterministic scan over the
current branch's existing originals. No secondary index or persistence format is
introduced. Reload and tree navigation use the same branch reconstruction as
line recall, including originals retained across native compaction.

Words are Unicode letter/number tokens with camel-case splitting. Rank is query
term coverage plus an exact-phrase bonus, with deterministic ties. Search uses OR
matching and explicitly warns about partial matches. It does not establish that
unmatched facts are absent. Line pagination by id remains the exhaustive path.

Chunks target 24 lines, prefer blank-line boundaries after 12 lines, and extend
across recognized contiguous stack regions. Source headers carry original output
line ranges. The budget covers whole chunks and their source headers using the
existing token estimator; the navigation header is extra. A too-small budget
returns no raw fragment and instructions for a larger budget or exact line read.
No retrieved message is subsequently rewritten or expired by this extension.

Hints list up to six actual identifiers/paths from hidden text. They are incomplete
and do not describe every hidden topic. Consecutive hidden sieve blocks share an
omission marker. Marker/hint overhead is included in the existing benefit gate.
The paragraph boundary rule adapts Winnow (MIT); see THIRD_PARTY_NOTICES.md.

## Expanded log scenarios

Python module pytest, Go build/vet, and Cargo check/clippy are classified alongside
the existing tools. On failed commands with recognizable failure and PASS lines,
only separate PASS-only blocks can enter Jev selection. All remaining blocks stay
verbatim, including arbitrary diagnostic prose; original error status is retained.
Existing stack/error/warning/location/summary protections still apply to PASS blocks.

The installed SDK truncates bash output before `tool_result`, and can convey a
full-output temp-file pointer in its text. Already-truncated logs pass through:
the extension does not claim to store bytes it never received. It does not read
that temp file automatically. Compound shell commands, installation output,
source viewers and search output remain outside semantic filtering.

## Real-workload inventory

`node bench/output-profile.ts > results/output-profile-v07.json`

This local-only inventory covers 26 non-temporary session files, all dates and
branches. It emits only aggregates. Categories use heuristic command matching;
repeated lines are not labeled as safely removable. Read output is about 2.74M
estimated tokens, bash view/search about 1.13M, and bash tests/build-check about
242K. Edit/write output is about 90K. No result passes the current eligibility
classifier. Of 148 long bash results, 117 contain shell composition syntax.

This limits expected daily sieve benefit. Supporting compound commands requires
understanding the resulting output provenance; simply recognizing a test command
somewhere in a shell string would admit unrelated source or data output.

## Validation methods

- Unit tests cover verbatim chunk reconstruction, trace boundaries, paragraph
  boundaries, source filtering, ranking, budgets, continuation, and exact recall.
- Installed SessionManager tests cover query recall on restored originals,
  compaction, and sibling isolation. An actual AgentSession startup test verifies
  that the SDK helper dispatches `session_start` before recall executes; it makes
  no model completion call and asserts prior message bytes remain unchanged.
- `bench/live/v07-recall.ts` uses antigravity/gemini-3.8-flash and fixed synthetic
  originals. A sees full output, B uses legacy id/line recall, C uses search and
  hints. Needed, unnecessary, and absent-component tasks have fixed filesystem
  acceptance. Only write and recall tools are available, preventing rerun bypass.
  This deliberately-hidden retrieval experiment does not establish sieve safety.
- `bench/live/v05-hardening.ts --focused --scenarios failure-exit` exercises actual
  commands and Jev with the same provider/model. Full retention after Jev timeout
  is successful fail-open behavior, not successful active compression.

The first retrieval attempt stalled; instrumentation revealed that the shared SDK
helper omitted `bindExtensions()`, so seeded originals were never restored. Runs
01 and 02 are retained but invalid for capability comparison. Run 03 fixed startup
and used an eight-turn limit; this can penalize lengthy legacy pagination. Run 04
uses a declared 20-turn/90-second ceiling and records filesystem success separately.
These attempts must not be pooled as identically configured repetitions.

Run 04's simplified legacy declaration omitted v0.6's default-limit description.
The final run 05 restores the exact v0.6 declaration: 18/18 passed, with lower
recall volume but higher latency in C, especially for absent facts. Full measured
tables and unsuccessful harness attempts are recorded in FINDINGS.md F29.
